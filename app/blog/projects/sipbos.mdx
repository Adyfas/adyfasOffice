<Heading>SipBos API</Heading>

SipBos API is a large-scale backend system designed to handle core e-commerce operations such as user management, product handling, transactions, and secure data workflows.  
This project serves as the backbone of an e-commerce platform, ensuring that all business logic, data processing, and integrations run reliably and securely.

The API was developed as a **solo backend project**, where I was fully responsible for designing, implementing, and maintaining the entire backend architecture. The primary goal was to build a system that is **secure, scalable, and easy to integrate** with various frontend applications or external services.

<Section />
<Heading>Project Background</Heading>

In an e-commerce environment, backend reliability is critical. Data consistency, transaction security, and authentication flows must work flawlessly to ensure a smooth user experience.

SipBos API was built to address these challenges by providing a centralized backend solution that manages complex data relationships, handles authentication securely, and processes transactions efficiently. This project demonstrates my ability to take full ownership of backend systems from planning to deployment.

<Section />
<Heading>My Role</Heading>

I worked as a **Backend Engineer**, taking full responsibility for the system end-to-end.  
All backend logic, database workflows, authentication mechanisms, and API endpoints were designed and implemented independently.

My responsibilities included:

<Section />
<Heading>Technical Implementation</Heading>

- **Prisma** was used as the ORM to manage database interactions, schema migrations, and data validation in a clean and maintainable way.  
- **Express.js** served as the core framework for building RESTful endpoints that handle authentication, products, carts, and transactions.  
- **PostgreSQL** acted as the primary relational database, ensuring data consistency for users, orders, inventory, and transaction history.  
- **Bcryptjs** was implemented to securely hash user passwords and protect sensitive credentials.  
- **JWT (Jsonwebtoken)** enabled stateless authentication, allowing secure access to protected API routes.  
- **Passport and OAuth strategies** were used to support third-party authentication such as Google login.  
- **Multer** handled file uploads, such as product images, with structured and secure storage workflows.  
- **Appwrite** was integrated for additional backend services like file storage and extended backend capabilities.  
- **Serverless-http** made it possible to deploy the Express-based API into serverless environments for better scalability and cost efficiency.
